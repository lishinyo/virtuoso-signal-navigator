# 常见问题与排错

## load 后没有面板

加载只定义函数。激活版图后运行 `lsnStart()`。检查 CIW 的语法错误及 `lsnCheckEnvironment()`，并确认路径属于运行 Virtuoso 的 Linux 主机。

## 提示多个版图窗口

脚本没有当前可确认的 maskLayout 窗口，又发现多个候选。激活目标版图，或用 `lsnStart(window(n))` 指定它。窗口编号可以从 `hiGetWindowList()` 取得。

## Source 显示为空或不对

先核对版图原有的源引用，不要默认原理图与版图同名。必要时使用 sourceOverride。它只选择原理图，不建立缺失的实例绑定。没有正确绑定，源端点可能显示 No bound layout pin。

## 正式 pin 缺失，但数字模块里明明有信号

检查模块 master 中是否有同名 label。纯几何导入数据可能保留文字与金属，却没有 OA net/term/pin。

0.3.0 的顺序是正式 pin、标签线索、模块范围。脚本通过版图已有 instTerm 或源到版图绑定确认所属实例，再在该实例内部找 label。缺少这两种依据时，不对整个芯片搜索同名文字来猜测位置。

核查：labelHints 是否开启、标签名的大小写及括号、标签是否在 master 的当前层级、是否有版图 instTerm 或实例绑定、是否需要 labelLayerMap。它不会递归查找模块内部任意深度的标签。

## Label anchor，没有 Label + metal

标签锚点附近没有命中指定 layer 上的金属。检查 layer 名、映射和半径。文字包围框与金属相交不等于锚点处有落点。较大的半径也可能命中其他图形，应检查候选而不是直接建立连接。

## 只看到 Block only

确认了实例位置，但没有找到正式 pin 或匹配的当前层级标签。脚本适配模块范围，帮助用户继续查找；模块中心不是端口位置。

## 定位到了空白网格

可能是层次或层可见性隐藏了实际几何。Display Levels Stop=0 时，子模块内容通常不可见；先把 Stop 设为至少 1，或按需要使用 Shift+F。再检查目标金属层可见性。

也可能是标签确实存在但没有对应金属，Status 会显示 Label anchor。此时该位置只作线索。

## 位置偏离器件

先确认 Layout/Schematic 是否正确，实例对应关系是否有效。脚本使用 master 坐标、实例旋转/镜像和编辑层级转换。检查是否在尚未重新绑定的编辑上下文中操作。

不要把标签文字框的中心当成其电气落点。若是阵列元素或复杂多对多映射，参见当前版本的限制，必要时提供匿名最小示例验证。

## 颜色或虚线与说明不同

自定义配色可能被关闭、临时目录不可写，或后续加载的显示文件改变了资源。重新 `lsnStart()` 初始化，或指定有效 tempDir。关闭 palette 时使用当前 y0/y1/y2，文字 Status 比颜色更可靠。

## 新增/改名标签没出现

点击 Refresh。标签对象按 master 缓存名称；已有对象移动会重新读取坐标，增删改名则需要重新建立索引。缓存也会过滤已经无效或名称不再匹配的旧对象。

## 大网络显示较慢

先关闭 Include metal extents。减少 maxMetalExtents、annotationLimit 或 chainLimit；必要时关闭 labelHints，先只看正式 pin。总览不扫描全芯片所有子层级，但首次索引某个大 master 的标签仍有成本。

同时限制版图显示层次；展开整片大量内部图形的开销属于编辑器重绘，不只来自导航脚本。

## Clear 后原有探针还在

这是预期行为。插件只删除自己创建并记录的高亮集，不调用“删除全部探针”一类全局操作。

## 如何报告问题

提供版本、关键 API 检查结果、最小复现步骤、实际 Status 与期望行为。优先用项目的通用测试或自行构造的匿名示例。不要在公开 issue 中提交真实芯片数据库、PDK、许可证文件或未经允许的版图截图。
